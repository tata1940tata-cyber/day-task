## 1. Общие сведения

### 1.1. Цель продукта
Простое приложение, в котором пользователь ведёт список задач **на текущий день**: добавляет задачи, отмечает выполненные, удаляет ненужные. Все данные хранятся локально на устройстве и переживают закрытие/убийство приложения и перезагрузку телефона.

### 1.2. Целевая аудитория
Пользователи iOS и Android, которым нужен «список на сегодня» без регистрации, облака, проектов и сложной настройки. Возраст 16+, базовая цифровая грамотность.

### 1.3. Принципы продукта
1. **Простота** — один основной экран, любое действие выполняется за ≤ 2 касаний.
2. **Offline-first** — приложение полностью работает без интернета; сеть не требуется ни для одной функции MVP.
3. **Надёжность данных** — задачи не теряются ни при каком сценарии завершения приложения.
4. **Приятная механика** — анимации подтверждают каждое действие, интерфейс «живой», но не отвлекает.

### 1.4. Вне рамок MVP (не разрабатывать, учитывать в архитектуре)
Напоминания и push-уведомления, повторяющиеся задачи, категории/теги/приоритеты, синхронизация между устройствами, аккаунты, виджеты на рабочий стол, Siri/Google Assistant, экспорт/импорт, шифрование. Перечислено в разделе 11 как бэклог v2.

## 3. Архитектура

### 3.1. Слои
```
presentation/  — экраны, виджеты, контроллеры/провайдеры, анимации
domain/        — сущность Task, правила (валидация, сортировка), use-кейсы
data/          — репозиторий задач, источник Hive, маппинг модели ↔ хранилище
```
Зависимости направлены вниз: presentation → domain → data. Слой данных можно заменить (например, на облачный API) без изменения UI.

### 3.2. Структура репозитория
```
lib/
  main.dart
  app/            # MaterialApp, темы, роутинг
  domain/         # task.dart, task_repository.dart (интерфейс), validation.dart
  data/           # hive_task_repository.dart, task_model.g.dart, migrations.dart
  presentation/
    today/        # экран «Сегодня», список, карточка задачи
    widgets/      # чекбокс, empty_state, undo_snackbar
    animations/   # общие токены анимаций (длительности, кривые)
test/             # unit- и widget-тесты
```

### 3.3. Модель данных `Task`

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | String (UUID v4) | да | Генерируется на устройстве, неизменяем |
| `title` | String | да | Текст задачи, 1–200 символов после trim |
| `createdAt` | DateTime (UTC, ISO-8601) | да | Момент создания, используется для сортировки |
| `completedAt` | DateTime? | нет | Момент отметки «выполнено»; `null` = не выполнена |
| `isCompleted` | bool | да | Денормализованное состояние для быстрой фильтрации |
| `position` | int | да | Порядок внутри дня (инкрементальный) |
| `schemaVersion` | int | да | Версия записи для будущих миграций |

**JSON-пример записи:**
```json
{
  "id": "3f6a1c9e-2b44-4c1d-9a10-0d2f7f5b1e77",
  "title": "Купить продукты",
  "createdAt": "2026-11-05T08:15:00.000Z",
  "completedAt": "2026-11-05T10:02:11.000Z",
  "isCompleted": true,
  "position": 3,
  "schemaVersion": 1
}
```

**Правила валидации `title`:**
- Trim пробелов по краям; пустая строка или строка из пробелов — запрещена (кнопка добавления неактивна).
- Максимум 200 символов; при превышении ввод блокируется с подсказкой.
- Дубликаты разрешены (пользователь может иметь две одинаковые задачи).
- Пустые строки и управляющие символы фильтруются.

**Ограничение объёма:** не более 100 задач в списке «Сегодня»; при попытке добавить 101-ю — сообщение «Достигнут дневной лимит задач».

### 3.4. Схема хранения (Hive)
- Box: `tasks_box`, ключ — `id`, значение — сериализованный `Task`.
- Отдельный box `meta_box` для служебных данных: `schemaVersion`, `lastOpenedDate`, `dailyTaskCount`.
- **Автосохранение:** запись в box синхронна и выполняется немедленно после каждого изменения (добавление, изменение статуса, удаление, редактирование). Никаких «сохранить» вручную.
- **Миграции:** при старте проверяется `schemaVersion`; неизвестная более новая версия — приложение работает в режиме read-only и показывает сообщение (защита от отката версии приложения).

## 4. Экраны и UX-состояния

### 4.1. Структура основного экрана «Сегодня» (единственный экран MVP)

```
┌──────────────────────────────────┐
│  Сегодня                    ☀/☾  │  ← шапка: название + переключатель темы (опц.)
│  Четверг, 5 ноября              │  ← дата локально, формат по локали
│  Выполнено 2 из 5               │  ← счётчик, обновляется мгновенно
├──────────────────────────────────┤
│  ☐ Купить продукты          🗑   │  ← карточка задачи (свайп = удалить)
│  ☑ Позвонить врачу          🗑   │  ← выполненная: приглушённый текст + зачёркивание
│  ☐ Сделать отчёт            🗑   │
│                                  │
│        (область прокрутки)       │
├──────────────────────────────────┤
│  [  Введите задачу…        ] [+] │  ← поле ввода + кнопка добавления
└──────────────────────────────────┘
```

Ввод задачи размещён **внизу экрана** (в зоне большого пальца), а не в виде FAB-диалога: добавление — самое частое действие.

### 4.2. Состояния экрана

| Состояние | Условие | Отображение |
|---|---|---|
| Загрузка | Первый запуск / чтение из хранилища | Скелетон из 3 строк на ≤ 300 мс; если чтение быстрее — без индикатора |
| Пусто | Задач нет | Иллюстрация (галочка/лист), текст «На сегодня задач нет» + подсказка «Добавьте первую задачу внизу» |
| Список | Есть задачи | Список по правилам FR-01 |
| Ошибка хранилища | Исключение при чтении/записи | Сообщение «Не удалось сохранить задачу. Попробуйте ещё раз» + кнопка «Повторить»; данные не удаляются |
| Лимит | 100 задач | Сообщение вместо добавления |
| Ошибка ввода | Пустой текст / > 200 символов | Кнопка «+» неактивна, тост с пояснением |

### 4.3. Навигация
- Один маршрут `today`; модальные bottom sheet: «Редактировать задачу» (по долгому нажатию) и «Подтверждение удаления» (опционально, см. FR-04).
- Кнопка «Назад» на Android закрывает приложение из главного экрана (стандартное поведение); на iOS — свайп/сворачивание системы.
- Deep links, боковое меню, таб-бар — не требуются.

### FR-01. Отображение списка задач на сегодня

**Описание.** Экран показывает задачи, относящиеся к текущей календарной дате (локальная таймзона устройства). Заголовок содержит локализованную дату. Под заголовком — счётчик «Выполнено X из Y».

**Сортировка и группировка.**
1. Невыполненные задачи — сверху, в порядке создания (новые добавляются **в конец** невыполненных, т.е. пользователь видит порядок, в котором их записал).
2. Выполненные — под невыполненными, в порядке отметки (недавно отмеченные — выше).
3. Визуально группы разделены подписью «Выполненные (X)» (при X > 0).

**Сценарии.**
- S1: Открытие приложения → список восстанавливается из хранилища за ≤ 300 мс.
- S2: Пользователь прокручивает список (50+ задач) — плавно, без просадок.
- S3: Смена даты на устройстве после полуночи: при следующем открытии приложения (или сворачивании/разворачивании) экран показывает задачи нового дня. Задачи предыдущих дней **не удаляются и не показываются** в списке «Сегодня»; хранятся в базе для будущих версий (раздел 11). В MVP история не отображается.

**Граничные случаи.**
- 0 задач → состояние «Пусто».
- 100 задач → прокрутка работает, счётчик корректен.
- Текст задачи до 200 символов, включая эмодзи и переносы строк (переносы допускаются, максимум 4 строки в карточке, далее «…»).
- Устройство без сети, в авиарежиме — всё работает.

**Критерии приёмки.**
1. Given пустое хранилище, When открыт экран, Then показано пустое состояние с подсказкой.
2. Given 5 задач (3 невыполненные, 2 выполненные), When открыт экран, Then первыми идут 3 невыполненные, затем подпись «Выполненные (2)» и 2 выполненные; счётчик «Выполнено 2 из 5».
3. Given список из 100 задач, When пользователь прокручивает его, Then кадровая частота ≥ 55 fps (замер через DevTools/FPS-график), подтормаживаний нет.
4. Given приложение закрыто, When оно открыто через 1 час / через день, Then список идентичен сохранённому (кроме случая смены даты — см. S3).

### FR-02. Добавление задачи

**Описание.** Поле ввода внизу экрана + кнопка «+» (и «Готово» на клавиатуре) создают задачу. Задача появляется в списке с анимацией (FR-06).

**Сценарии.**
- S1: Ввод текста → кнопка «+» активна → нажатие → задача в конце невыполненных, поле очищается, клавиатура остаётся открытой для следующего ввода (серийное добавление).
- S2: Enter/«Готово» на клавиатуре = нажатие «+».
- S3: Кнопка «Назад» при открытой клавиатуре — сначала закрывает клавиатуру.

**Граничные случаи.**
- Пустой или пробельный ввод → «+» неактивна (визуально затемнена).
- > 200 символов → ввод останавливается, показывается подсказка «Максимум 200 символов».
- Текст с ведущими/конечными пробелами → сохраняется без них.
- Вставка длинного текста из буфера → обрезка до 200 символов с уведомлением.
- Лимит 100 задач → сообщение, добавление невозможно.

**Критерии приёмки.**
1. Given пустое поле, When введён текст «Тест» и нажат «+», Then задача «Тест» видна в списке, поле пустое, фокус в поле.
2. Given текст «   кот   », When добавлен, Then в списке «кот».
3. Given пустое поле, Then кнопка «+» неактивна и не реагирует на нажатие.
4. Given 200 введённых символов, When введён 201-й, Then он не добавляется, показана подсказка.
5. Given задача добавлена, When приложение убито и открыто снова, Then задача на месте (проверка сквозного сохранения).

### FR-03. Отметка задачи как выполненной / снятие отметки

**Описание.** Тап по чекбоксу (или по всей строке задачи — на выбор реализации, зафиксировать до старта разработки) переключает статус. Действие обратимо в любой момент.

**Поведение при включении.**
- Чекбокс анимируется в «галочку» (см. FR-06).
- Текст получает зачёркивание и снижение контраста (opacity 0.6, но не ниже порога доступности AA — проверить контраст ≥ 4.5:1 для основного текста, для выполненных допускается ≥ 3:1 как secondary).
- Через 300 мс карточка плавно перемещается в группу «Выполненные» вниз списка.
- Счётчик «Выполнено X из Y» обновляется мгновенно.

**Поведение при выключении.**
- Зеркально: карточка возвращается в конец группы невыполненных (позиция определяется `position`/`createdAt`; допускается вариант «в конец невыполненных» — зафиксировать в реализации).
- `completedAt` сбрасывается в `null`.

**Сценарии.**
- S1: Отметить → передумать → снять отметку: задача снова активна.
- S2: Быстрые множественные тапы по разным чекбоксам — без «заеданий» и пропущенных анимаций (допускается прерывание предыдущей анимации).
- S3: Отметка всех задач подряд — список остаётся отзывчивым.

**Граничные случаи.**
- Двойной тап по одному чекбоксу быстрее 200 мс → учитывается как 2 переключения (итог — исходное состояние), анимация не «ломается».
- Отметка при открытом поле ввода с текстом → текст в поле не теряется.

**Критерии приёмки.**
1. Given невыполненная задача, When тап по чекбоксу, Then за ≤ 300 мс она визуально отмечена и перемещена вниз; счётчик увеличен.
2. Given выполненная задача, When тап по чекбоксу, Then она снова невыполненная и находится среди невыполненных; счётчик уменьшен.
3. Given любой статус, When приложение перезапущено, Then статус сохранён.
4. Given 10 быстрых переключений подряд, Then интерфейс не зависает, итоговое состояние каждого чекбокса соответствует числу нажатий (чёт/нечёт).

### FR-04. Удаление задачи

**Описание.** Два доступных способа (обязательны оба):
1. **Свайп влево по карточке** (с иконкой корзины, подтверждающей действие) — основной способ.
2. **Долгое нажатие (≈ 500 мс)** → bottom sheet «Удалить задачу?» с кнопками «Удалить» / «Отмена» — альтернатива и способ для пользователей с нарушениями моторики.

После удаления показывается **snackbar «Задача удалена» с кнопкой «Отменить» (Undo) в течение 5 секунд**. Нажатие «Отменить» восстанавливает задачу на прежнюю позицию с исходными полями (`id` сохраняется).

**Сценарии.**
- S1: Свайп → карточка уезжает с анимацией и схлопыванием высоты → snackbar с Undo → ничего не нажато → задача удалена окончательно.
- S2: Свайп → Undo → задача возвращается на место с обратной анимацией.
- S3: Удаление нескольких задач подряд → каждый snackbar заменяет предыдущий, но Undo действует только на последнюю удалённую задачу (зафиксированное поведение).
- S4: Долгое нажатие → подтверждение → удаление.

**Граничные случаи.**
- Свайп на 50% ширины и отпускание → удаление; свайп < 50% → карточка возвращается на место (анимация возврата 200 мс).
- Удаление последней задачи → экран переходит в состояние «Пусто».
- Undo после закрытия snackbar (через 5 с) → невозможен; задача удалена безвозвратно (из MVP нет корзины).
- Удаление при сохранённом тексте в поле ввода → текст не теряется.

**Критерии приёмки.**
1. Given карточка задачи, When свайп влево ≥ 50% ширины, Then она удаляется с анимацией и появляется snackbar «Задача удалена · Отменить».
2. Given показанный snackbar, When нажато «Отменить» за 5 с, Then задача восстановлена на прежней позиции с прежним статусом.
3. Given snackbar скрыт по таймеру, Then задача удалена из хранилища (после перезапуска её нет).
4. Given долгое нажатие, Then открыто подтверждение; «Отмена» не удаляет ничего.
5. Given удалена последняя задача, Then показано пустое состояние.

### FR-05. Сохранение задач на устройстве (персистентность)

**Описание.** Все изменения пишутся в локальное хранилище немедленно и атомарно. Приложение не требует кнопки «Сохранить».

**Требования.**
- Сохранение при: добавлении, изменении статуса, удалении, редактировании, изменении позиции.
- Восстановление при: обычном закрытии (swipe-up), «убийстве» процесса системой, падении приложения, перезагрузке устройства, обновлении приложения (сохранение данных между версиями), офлайн-работе.
- Время записи одной операции ≤ 50 мс (не блокирует UI).
- Данные не покидают устройство. Резервное копирование ОС (iCloud/Google Backup) — на усмотрение ОС, документируется в политике конфиденциальности.

**Сценарии и критерии приёмки.**
1. Given 10 добавленных задач, When приложение принудительно завершено (swipe из multitasking), Then при следующем открытии все 10 задач на месте в исходном порядке и со статусами.
2. Given изменённый статус, When устройство перезагружено, Then статус сохранён.
3. Given любое действие CRUD, When хранилище физически недоступно (имитируется в тестах), Then показано сообщение об ошибке, состояние UI консистентно, повтор действия возможен.
4. Given обновление приложения с v1 на v1.1, Then данные прошлой версии читаются без потерь (проверка миграции).

### FR-06. Анимации

**Общие требования.**
- Плавность: 60 fps на среднем Android-устройстве (например, класса Snapdragon 6-й серии / аналог); на экранах 120 Гц — без искусственного ограничения.
- Все анимации — «неявные» (мгновенный отклик на действие пользователя); задержка реакции на касание ≤ 100 мс.
- **Reduce Motion / «Уменьшить движение»:** при включённой системной настройке анимации заменяются мгновенным изменением состояния (или fade ≤ 100 мс). Поддержка обязательна на обеих ОС.
- Анимации не должны блокировать ввод: прерывание текущей анимации новым действием — допустимо и ожидаемо.
- Все длительности — константы в одном файле `animations/tokens.dart`, чтобы менять их в одном месте.

**Спецификация анимаций.**

| # | Событие | Визуальный эффект | Длительность | Кривая | Реализация (Flutter) |
|---|---|---|---|---|---|
| A1 | Появление задачи в списке | Новая карточка проявляется (opacity 0→1) и выезжает снизу на 16 px; список плавно раздвигается | 250 мс | easeOutCubic | `AnimatedList` + `SizeTransition`/`SlideTransition` |
| A2 | Отметка «выполнено» | Галочка прорисовывается в чекбоксе (stroke-draw), фон чекбокса заливается акцентным цветом | 200 мс | easeInOut | `AnimatedContainer` + `CustomPainter` (или `AnimatedSwitcher`) |
| A3 | Зачёркивание текста | Линия прочерчивается слева направо поверх текста | 200 мс | easeOut | `AnimatedFractionallySizedBox` / кастомный painter |
| A4 | Перемещение выполненной задачи вниз | Карточка «переезжает» на новую позицию без скачков | 300 мс | easeInOutCubic | `AnimatedList` remove+insert с общим `GlobalKey` / `AnimatedSwitcher` |
| A5 | Снятие отметки | Зеркально A2+A3+A4 (обратное перемещение) | 300 мс | easeInOutCubic | то же |
| A6 | Удаление свайпом | Карточка уезжает влево с opacity 1→0, высота схлопывается, соседние съезжаются | 250 мс | easeInCubic | `Dismissible` / `Slidable` + `SizeTransition` |
| A7 | Возврат карточки при недостаточном свайпе | Карточка плавно возвращается на место | 200 мс | easeOutBack (допускается лёгкий overshoot ≤ 4 px) | `Dismissible` (встроено) |
| A8 | Undo (восстановление задачи) | Обратная A6: карточка выезжает снизу в позицию | 250 мс | easeOutCubic | `AnimatedList` insert |
| A9 | Первый показ списка при запуске | Карточки появляются каскадом (stagger) с шагом 30 мс, максимум 8 карточек | 8 × 150 мс | easeOut | `Interval`-кривые в `AnimationController` |
| A10 | Смена темы (если делается переключатель) | Плавный переход цветов | 300 мс | easeInOut | `AnimatedTheme` |
| A11 | Появление snackbar / bottom sheet | Выезд снизу + fade | 250 / 300 мс | easeOutCubic | встроенные `SnackBar`, `showModalBottomSheet` с кастомной кривой |
| A12 | Ошибка ввода (пустой текст) | Лёгкое горизонтальное «покачивание» поля (±6 px, 2 цикла) | 300 мс | easeInOut | `AnimationController` |

**Критерии приёмки.**
1. Given любое действие из A1–A12, Then анимация воспроизводится ровно один раз, без «дёрганья» и без задержки отклика > 100 мс.
2. Given 60-секундный сценарий «добавить 5 задач → отметить 3 → удалить 2», Then средний FPS ≥ 55 на тестовом Android-устройстве, jank-кадры (Frame timing > 16 мс) ≤ 3%.
3. Given включённая настройка «Уменьшить движение», Then анимации заменены мгновенными переходами/fade ≤ 100 мс.
4. Given быстрые повторные действия (5 тапов/сек), Then анимации корректно прерываются, визуальных артефактов (моргание, двоение, «прыгающая» высота) нет.

### FR-07. Кроссплатформенность

**Описание.** Одна кодовая база даёт нативное поведение на обеих ОС.

**Требования.**
- На iOS — нативные паттерны: навигация без нижней панели, поведение клавиатуры, swipe-back системный, виджеты Cupertino там, где это уместно (диалоги, pickers); на Android — Material 3, ripple-эффекты, системный back.
- Рекомендуется адаптивность через `Platform`/`Theme.of(context).platform`: различия допускаются в стиле, **не в функциональности**.
- Push-уведомления, биометрия и прочие нативные модули в MVP не используются — расхождений поведения быть не должно.
- Один репозиторий, одна ветка релиза, сборка под обе ОС из одного коммита.

**Критерии приёмки.**
1. Given один и тот же код-коммит, Then собираются Android-сборка (AAB+APK) и iOS-сборка (TestFlight) без правок бизнес-логики под платформу.
2. Given сценарий приёмки FR-01…FR-05, Then он пройден и на iOS-устройстве, и на Android-устройстве (см. раздел 10).
3. Given iOS, Then системный свайп-жест/клавиатура работают по конвенциям Apple; Given Android, Then кнопка «Назад» и ripple работают по конвенциям Google.

## 7. Этапы разработки и форматы сдачи

> Сроки ориентировочные для одного разработчика (при работе команды этапы могут идти параллельно). Итого: **3–4 недели** до релизной сборки.

### Этап 0. Подготовка и проектирование — 1–2 рабочих дня
**Содержание:** создание репозитория, настройка проекта Flutter, CI (сборка debug-варианта на каждый коммит), оформление дизайн-макета экрана «Сегодня» (Figma) с состояниями пусто/список/ошибка и токенами анимаций, утверждение макета заказчиком.
**Формат сдачи:** ссылка на репозиторий + Figma-макет + список открытых вопросов.
**Критерии готовности:** проект запускается на эмуляторе iOS и Android («Hello world»), макет утверждён.

### Этап 1. Ядро и хранение — 3–5 рабочих дней
**Содержание:** модель `Task`, слой данных (Hive, репозиторий, миграции), экран «Сегодня», отображение списка по FR-01, добавление задачи по FR-02 (без анимаций), сохранение по FR-05.
**Формат сдачи:** рабочая debug-сборка на обе ОС (APK + установка на реальное устройство iOS через TestFlight internal или cable), unit-тесты модели и репозитория (≥ 10 кейсов), короткое видео-демо 1–2 мин.
**Критерии готовности:** FR-01, FR-02, FR-05 пройдены вручную; задачи переживают убийство приложения.

### Этап 2. Полный CRUD — 2–3 рабочих дня
**Содержание:** отметка выполнения FR-03, удаление FR-04 (свайп + долгое нажатие + Undo), счётчик, граничные случаи (лимит 100, валидация 200 символов).
**Формат сдачи:** debug-сборка, unit + widget-тесты (≥ 15 кейсов), чек-лист пройденных сценариев.
**Критерии готовности:** FR-03, FR-04 пройдены; ни один сценарий не теряет данные.

### Этап 3. Анимации и визуальная полировка — 3–4 рабочих дня
**Содержание:** все анимации A1–A12 по спецификации FR-06, пустые состояния, скелетон загрузки, snackbar Undo, поддержка «Уменьшить движение», оптимизация производительности (замер FPS).
**Формат сдачи:** debug-сборка + видео-демо каждого типа анимации (по 5–10 сек), замер FPS-графика вложенным в отчёт (скриншот/лог DevTools).
**Критерии готовности:** FR-06 пройдено; FPS ≥ 55 в тестовом сценарии; reduce motion работает.

### Этап 4. Кроссплатформенная адаптация, темы, локализация — 2–3 рабочих дня
**Содержание:** платформенные различия (§ FR-07), светлая/тёмная тема, RU/EN локализация, доступность (TalkBack/VoiceOver, размеры касаний, контраст), системный масштаб шрифта.
**Формат сдачи:** сборки на обе ОС, скриншоты обеих тем на iOS и Android, аудио/видео-демо работы скринридера, список строк локализации (`.arb`-файлы).
**Критерии готовности:** FR-07 и раздел 6 (доступность, локализация, темы) пройдены.

### Этап 5. Тестирование и релиз — 3–5 рабочих дней
**Содержание:** сквозное ручное тестирование по чек-листу раздела 10 на 4 устройствах (iPhone с iOS-последней и предыдущей, Android-флагман и слабый Android ≤ 2 ГБ RAM), исправление багов, performance-профилирование, подготовка релизных сборок, метаданные для сторов.
**Формат сдачи (итоговый пакет — см. раздел 9):** подписанный AAB + APK, TestFlight-сборка, исходный код в `main`, README, CHANGELOG, отчёт QA, видео-демо основного сценария.
**Критерии готовности:** все критерии приёмки разделов 5–6 выполнены; известных багов severity 1–2 нет; заказчик подписал акт приёмки.

## Приложение A. Глоссарий
- **Задача (Task)** — элемент списка дел с текстом и статусом выполнения.
- **Undo** — временное (5 секунд) восстановление удалённой задачи из snackbar.
- **Offline-first** — все функции работают без сети, данные локальны.
- **Reduce Motion** — системная настройка доступности, уменьшающая анимации.
- **AAB / APK / TestFlight** — форматы дистрибуции для Google Play, ручной установки Android и тестирования iOS соответственно.
